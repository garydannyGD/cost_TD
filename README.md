# Paw & Profit — Cost Accounting Tower Defense

A colourful, complete tower-defense game for Diploma in Accounting: Cost Accounting Chapter 1 (DAC2013 / BAC143). Twenty original questions, ten waves, four selectable animal families, twelve family-specific towers, four hero powers, animated canvas graphics and three original music tracks.

## Files

- `index.html`: homepage, character selection, game controls, questions and report.
- `style.css`: responsive pastel interface and homepage animations.
- `script.js`: labelled editable question bank; family/tower configurations; combat, drawing, music and learning logic.
- `README.md`: instructions and validation.
- `FULL_CODE.md`: complete source of those four files, labelled with exact filenames.

No external assets, installation, build, backend, account or API key. Open `index.html` after extracting the ZIP. Keep all three web files in the same folder. All graphics are generated by canvas/CSS or system emoji; emoji appearance may vary by device. Music is generated offline using Web Audio, so there are no missing song downloads.

## Play

1. Choose a cat, dog, pig or cow. Each has distinct tower statistics, appearances and a power.
2. Start the mission. Before each wave, solve two learning questions. Each successfully repaired question grants four building stars, including after a retry. Everyone can earn the same resources.
3. Select a tower from the sidebar, then click/tap one of the eight empty numbered plots. Towers shoot automatically during a wave. Tap a built plot to inspect it, upgrade it (3 stars, maximum level 3) or sell it (75% of stars invested, rounded down).
4. Send the wave when ready. Place towers near bends and cover different sections of the path. Build and upgrade during combat too. Towers prioritise the furthest-progressed enemy in range. Splash attacks hit nearby enemies; slowing towers reduce movement speed.
5. Use the family hero power once per wave. Cat: 18 damage to every active enemy and a 3-second stun. Dog: 12 damage and 5 village hearts. Pig: 35 damage to every active enemy. Cow: 8 damage, 6-second slow and 3 village hearts. Healing caps at 20.
6. Defeat all blobs in ten waves. Waves 5 and 10 include a larger boss. Every surviving wave grants 2 stars and heals 2 hearts.
7. If village health reaches zero, Retry wave restores 20 hearts and grants 6 rescue stars. Adjust your towers, then send the same wave again. Learning marks and solved questions are preserved.

Keyboard: Tab navigates character choices, tower choices, plot buttons, powers and controls; Enter/Space activates focused buttons. In question dialogs, keys 1–4 select answers. Escape returns to the village or ends final practice. The eight numbered plot buttons provide keyboard alternatives to clicking the canvas. Touch: tap controls/plots. There are no dragging gestures or precision shooting requirements.

Pause freezes combat; Speed toggles ×1/×2 combat simulation. Switching away from the tab pauses a battle; press Resume when back. The optional elapsed clock never ends a question or affects marks. Untimed is the default. Questions and feedback always pause combat. Question feedback stays visible until Continue or Try again is selected. Incorrect answers remain available to retry; Continue returns to the village without marking them solved. The next Learning challenge reopens an unresolved question.

The large animal sprite is the hero; the hero power is activated by its named button. Hero movement is decorative; tower position and power timing are the main player decisions. Animated blobs walk the path, towers launch icon projectiles, flowers decorate the meadow and confetti particles mark hits. Reduced-motion preferences reduce decorative movement, while essential enemy/projectile movement remains visible.

## Music

Choose Meadow Morning, Bubble Parade or Moonlight Paws using the track selector. Click **Music: off** to enable playback. The tune loops until switched off; adjust the volume slider. Music starts only after a user action and suspends when the tab is hidden. These are original instrumental synthesized melodies, not commercial recordings or vocal songs. Music requires browser Web Audio support; a failure does not prevent gameplay.

## Learning and assessment

Aligned with the user's Chapter 1 notes, August study plan and Chapter 1 progress-test marking concepts read for this project. Covers purpose/users, units/centres, responsibility centres, cost classification, direct and indirect costs, prime/production cost, fixed/variable/stepped/semi-variable behaviour, a graph, high–low and its limitations, functional classification, flexible and flexed budgets. The final question transfers high–low estimation to a new laundry business.

A correct first submitted answer earns one learning mark, maximum 20. Wrong-first questions earn no first-attempt mark after correction, but successful retries earn the same building stars and unlock progress. Repeated clicks cannot duplicate marks or resources. The report lists first answers, correct answers, explanations and recovered questions. Final practice does not change the report. Village hearts, rescue count, speed and elapsed time never reduce learning marks. Print learning report uses the browser print dialog.

This is formative learning, not a secure exam: answers are available in the public JavaScript source. No student data is transmitted, stored persistently or sent to a lecturer. Refreshing/closing clears mission progress. Home abandons the current mission; restarting resets it. Allow roughly 25–40 minutes with calculation time; combat itself is shorter.

## Upload and publish on GitHub Pages

1. Extract the ZIP and open its `cost-quest` folder.
2. Create/open a GitHub repository, for example `cost-quest`. A public repository is the straightforward free option.
3. Use **Add file → Upload files**. Upload `index.html`, `style.css` and `script.js` directly to the repository root. Do not upload the ZIP alone or nest these files inside another folder. The two Markdown files are optional for hosting.
4. Commit the changes to `main`. If replacing the earlier escape-room game, replace all three web files together.
5. Open **Settings → Pages → Build and deployment**. Set Source to **Deploy from a branch**, branch to **main**, folder to **/(root)**; Save.
6. Wait for deployment and use the Visit site link displayed in Pages settings. Example project URL: `https://YOUR-USERNAME.github.io/cost-quest/`.
7. If an older version appears, wait for deployment and hard-refresh (Ctrl+F5 on Windows).

Official guide: https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site

## Edit questions and game content

The top of `script.js` is labelled `EDITABLE QUESTION BANK`. Keep 20 entries for the current ten-wave/two-question structure. Replace titles, options and explanations freely. `answer` is zero-based: 0 = first option, 1 = second, 2 = third, 3 = fourth. Use unique IDs and four plausible options. Keep the last item as a new-example transfer check. The legacy `room` metadata is unused in tower defense. Optional `data` contains trusted local table/SVG HTML; other strings render as text. Do not paste untrusted HTML. Validate calculations and update explanations when editing numbers.

Below the bank, `FAMILIES` labels each character, tower and its cost/damage/range/fire interval/splash/slow properties. Powers are implemented in `power()`. `PATH` defines the enemy route and `PLOTS` the eight tower positions. `TRACKS` contains the three original MIDI-note melodies. Homepage text is in HTML; colours/layout are in CSS. Changing question count requires adapting the two-question indexing, ten-wave completion, labels and homepage/report denominator together.

## Checks performed and limits

JavaScript syntax passed `node --check`. Automated Node tests with a simulated DOM and canvas ran all ten combat waves for every family using only earned stars, a mixed-tower build and upgrades. All four campaigns completed with 20/20 marks. Additional checks covered wrong-answer retry, one-time star awards, duplicate scoring prevention, wave gates, one power use per wave, pause, restart, zero-health defeat/rescue without loss of marks, and execution of the drawing code. The question bank and calculations carry over from the checked Chapter 1 game.

These are logic/simulation checks, not real browser rendering or audio playback. Desktop/mobile layout, native dialog focus, touch and audible music were not executed in this environment. Use this checklist before teaching:

- [ ] Open locally and on GitHub Pages; confirm no missing CSS/JS or console errors.
- [ ] Select each of the four heroes; confirm its three towers and named power change.
- [ ] Solve questions with mouse/touch and 1–4 keys. Check wrong answers, Try again, Continue and closing/reopening an unresolved question.
- [ ] Repeated clicks award stars/marks only once. A wrong-first answer remains zero marks after a successful retry but earns four stars.
- [ ] Build using canvas plots and numbered keyboard plot buttons; upgrade twice, check max level, sell, and test insufficient stars.
- [ ] Send a wave; confirm moving enemies, projectiles, damage, splash/slow, health loss and hero power once per wave.
- [ ] Pause/Resume, ×2 speed, hide/return to the tab, defeat/rescue/rebuild and restart work.
- [ ] Finish ten waves and all twenty questions; review explanations, practise missed questions without changing marks, and print the report.
- [ ] Enable all three music tracks; test volume, mute and switching tabs. The game works with music off.
- [ ] Check 360px phone, tablet and desktop widths; rotate device, zoom to 200%, scroll dialogs and verify all controls remain reachable.
- [ ] Tab through controls; check visible focus and Escape; test with reduced-motion preference.
